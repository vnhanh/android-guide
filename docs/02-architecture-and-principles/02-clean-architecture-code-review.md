# Clean Architecture, Code Review & Team Mentorship

## ⚖️ 1. Technical Debt Management & Code Review Strategy

```
                              ┌────────────────────────┐
                              │ Code Review Triggered  │
                              └───────────┬────────────┘
                                          │
                                    Risk Assessment
                                          │
                   ┌──────────────────────┴──────────────────────┐
                   ▼                                             ▼
          [High-Risk Violation]                        [Safe/Minor Violation]
     (Memory leak, crash, security)              (Naming convention, layer split)
                   │                                             │
                   ▼                                             ▼
        Balk Merge & Pair Refactor                    Approve & File Tech Debt Ticket
```

### Risk Assessment Matrix
- **Block Merge**: Memory leaks, Main thread I/O, security flaws, ANR risks. Conduct immediate 1-on-1 pair programming refactor.
- **Merge & Track**: Naming convention deviations or sub-optimal module placement that doesn't impact runtime stability. Approve to satisfy release deadlines and create a Linear/Jira Tech Debt item.

## 🔒 2. Security Architecture: JWT Token Specification

A JSON Web Token (JWT) consists of three dot-separated components: `Header.Payload.Signature`.

```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkhhbmgifQ.Signature
```

1. **Header**: Specifies signing algorithm (`HS256`, `RS256`) and token type (`JWT`).
2. **Payload**: Contains claims (user ID, expiration timestamp `exp`, roles).
3. **Signature**: Cryptographic signature generated by combining encoded header, payload, and a secret key to ensure tamper-resistance.
